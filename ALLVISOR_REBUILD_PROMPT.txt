1. PRODUCT VISION
--------------------------------------------------------------------------------

Allvisor is a bilingual (Bahasa Malaysia / English) multi-tenant operations platform for Malaysian small businesses.

Core promise:
- One codebase, many business verticals ("niches")
- Shared CRM, invoicing, inventory, accounting, LHDN e-Invoice
- Niche-specific operations unlocked by a capability engine
- Split UX: Owner/Admin oversight vs Staff floor operations
- Malaysian business reality: MYR currency, Malaysian holidays, LHDN MyInvois, IC numbers, BM/EN UI

Primary deep niches (first-class UX):
1. Clinic
2. Retail / commerce POS
3. Gym (memberships, check-ins, classes, walk-in timed sessions)
4. Tuition (subjects, classes, attendance, assessments)
5. Owner Ops Brain (alerts, tasks, AI supervisor, performance)

Also supported (capability + CRUD modules, often via a generic NicheModulePage):
salon, pharmacy, optical, workshop, vet, fashion, electronics, wholesale, laundry, physio, lab, fnb, hotel, property, courier, contractor, manufacturing, legal, events, farm

Total niches: 25.

Target users:
- Business owners / co-admins
- Supervisors / managers / floor staff
- Marketing prospects via /start lead funnel

3. HIGH-LEVEL ARCHITECTURE
--------------------------------------------------------------------------------

Pattern:
- Multi-tenant organizations
- Users belong to orgs via memberships (staff roles)
- Niche on the organization drives capabilities, navigation, vocab, and theme
- Capability engine is the single source of truth for feature access
- Audience split:
  - admin audience = owner / admin → Owner Zone + admin dashboard
  - staff audience = supervisor / manager / staff → floor dashboard + Manager Zone

Suggested structure:

allvisor/
  src/
    app/
      [locale]/
        (app)/                 # authenticated app shell
        login/, register/, onboarding/, start/, student/
      api/                     # cron + unsubscribe
      actions.ts               # core server actions
      gym-actions.ts
      retail-actions.ts
      niche-actions.ts
      tuition-actions.ts
      ops-actions.ts
      marketing-actions.ts
      globals.css
    components/                # AppShell, POS, dashboards, gym walk-in, etc.
    lib/                       # niches, roles, LHDN, AI, alerts, supabase
    modules/                   # thin niche capability exports
    i18n/
    middleware.ts
  messages/                    # en.json, ms.json
  supabase/migrations/        # sequential SQL 001 → 036+
  public/
  vercel.json
  .env.example

Key architectural rules:
1. Pages/actions MUST gate with hasCapability() / requireCapability(), not scattered niche === "clinic" checks.
2. Shared CRM/invoices/inventory/accounting/admin pages serve all niches.
3. Niche-specific deep workspaces exist where needed (POS, appointments, gym walk-in, etc.).
4. Many specialty niches can use a generic NicheModulePage CRUD pattern.
5. RLS must ensure Org A never sees Org B data.
6. Prefer Server Components + Server Actions + ActionForm patterns.

4. DOMAIN CONCEPTS (IMPORTANT VOCABULARY)
--------------------------------------------------------------------------------

Niche:
  Business vertical chosen at signup (clinic, retail, gym, ...). Drives capabilities, nav, labels, theme.

Capability:
  Atomic feature flag unit, e.g. pos, appointments, memberships, class_checkin, batch_expiry, walk-in related flows, etc.

Engine groups:
  care | commerce | hybrid | fnb | hospitality | specialty

Organization / branch:
  Tenant. Multiple orgs can be linked as branches (branch_links / branch_link_requests). Active org stored in cookie.

Membership (staff):
  Row in `memberships` table: user ↔ organization + role.
  Roles: owner | admin | supervisor | manager | staff
  DO NOT confuse with gym memberships.

Gym membership:
  Customer plan stored in `gym_memberships` (separate table from staff memberships).

Walk-in (gym):
  Counter-paid timed session for non-members / day visitors.
  Has duration, expiry, status (active / expired / done), IC/address optional.
  Packages = admin-defined priced minute bundles (e.g. 1 hour / 2 hours).
  Presence notifier alerts staff when session expires.

Check-in:
  Logged presence for gym members (`gym_checkins`).

Class schedule:
  Shared capability. Tuition and gym can reuse class tables/UI (tuition_classes) with niche-specific copy.

Audience:
  admin vs staff UX experiences.

Admin Zone / Manager Zone:
  Password-locked sensitive area for admin/accounting/lhdn (and alerts for staff managers).
  Password hash stored on org; default pattern conceptually `{OrgName}{year}`; unlock via cookie.

Ops Brain:
  Alerts + tasks + rules (refund_rate, repeat_voids, cash_variance, stock_leak, etc.) + cycle counts.

AI Supervisor:
  Daily cached briefing + owner chat widget. Uses LLM if configured, else rule-based text. Can notify via Telegram.

LHDN / MyInvois:
  Malaysian e-invoice submission. Allvisor acts as intermediary for shops.
  Modes: intermediary (default) or taxpayer (self-test).
  Environments: sandbox | production.

Subscription plans:
  free | starter | growth | pro
  Gate staff counts, invoice volume, LHDN features, etc.

Vocab:
  Niche-specific entity words: patient (clinic) vs customer (retail) vs member (gym) vs student (tuition), etc.
  Use niche-vocab mapping in UI strings.

HVCO /start funnel:
  Marketing acquisition landing + playbook + thank-you, with Resend email sequence for leads.

4. Admin/Manager Zone password unlock cookie for sensitive sections

Login routes:
